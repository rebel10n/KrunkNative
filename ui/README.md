# ui/ — the Krunker v7.1.4 menu as HTML/CSS

This is Krunker v7.1.4's own menu page, rendered by Krunker Box Office's in-house
HTML/CSS engine in the native client and by the browser in the web build (see
`doc/html-ui-engine.md`). Its behaviour is C (`client/src/ui/`), not JavaScript. The
goal is pixel parity with the real page in its loaded, logged-out, menu-open state of a
returning player (v7's `fullMenu()`; the FRVR first-time gradual menu and bot tutorial are
not ported): everything v7 shows a guest is shown here too, with the same markup,
stylesheets, fonts, icons and animations. It is generated by `make ui-import`
(`tools/ui-import/`, `--ref v7`) apart from the Krunker Box Office files listed under "Our files";
regenerate rather than edit the imported files. The Krunker v3.1.1 page this replaced is
on the `v3.1.1` branch/tag.

## Provenance

Imported from the v7.1.4 `public/` tree (`/home/user/jails/kru/src/Krunker_v7.1.4/public`)
by `tools/ui-import/import.py` (details and options: `tools/ui-import/README.md`):

  mithril, frvr, index.js, the libs, the inline scripts: `_isMobile`, captcha callbacks,
  `randInt`, the early `scaleBase` copy, the `#mainLogoFace` pick, the FTUE / gradual-menu
  block), comments, `og:` metas and PWA links removed; `?build=`/`?v=` stripped;
  `https://assets.krunker.io/` (rewritten to the local tree at run time by v7's hook.js) and
  root-relative URLs made relative; external `<a href>`s neutralised (`href="#"
  data-ext-href=...`, opened in a browser by C); `<canvas id="canvas">` (the web build's
  WebGL target) added as the first body child, `css/krunknative.css` + `css/hud.css` linked
  after Krunker's stylesheets, `js/kn-shim.js` + `js/loader.js` before `</body>`.
  Intentional difference: the footer's "Experiments" link (`abTestsPopup()`, v7's A/B test
  opt-in) and the separator after it are dropped, so Contact / Terms / Changelog stay evenly
  spaced; Krunker Box Office runs no A/B tests.
- Stylesheets `css/main.css`, `css/bundled/bundledStyles.min.css`, `css/main_custom.css`,
  `css/flag.css`, `css/material-icons.css`, `css/material-icons-outlined.css`,
  `css/material-symbols-outlined.css`, `css/google-play.css`, `css/google-secular-one.css`,

  ChakraPetch, Play subsets, Secular One, Material Icons + Outlined, lucon, ...); each

- `windows/`: the markup v7's own client writes into `#menuWindow` for every
  `showWindow(n)` (a returning guest, default settings), captured from the real page in
  headless Chromium (`tools/ui-import/capture_v7_windows.js`, kept as
  `tools/ui-import/krunker-windows-v7.json.gz`) and split by `windows_v7.py`: `<n>.html`,

  `docs/versions.txt`, the Changelog). Cosmetic pickers keep their first 4 cards as

  clones are dropped (`tools/ui-import/README.md`).
- Images: every local file the pages, stylesheets and window templates reference, plus
  what the C UI generates (`tools/ui-import/menu-assets-v7.txt`). v7.1.4's reconstructed
  tree lacks a few files Krunker Box Office uses (level icons 7..99, the rank badge, prize wheel
  cards, `img/noimg.png`, `img/wallbang_0.png`, ...): those come from v3.1.1 (`v3:` lines).
  References v7 itself 404s on (flag SVGs, `img/streaks/1..6`, `img/esports/*`,
  `img/customize/other.png.png`, ...) are listed by the import and stay 404s here too.
  `KRUNKNATIVE_HTML_IMAGE_LOG=1|<file>` logs every image the native engine fails to load.

Season / challenge images v7.1.4 loaded from its CDN and its tree lacks (`img/chals/icon_<n>.png`,
`img/chals/hed_{1,2,4}.png`, the Weapon Challenges cards `img/chals/weapon_*.png`,
`img/battlepass/logo_white.svg` and `krunkies.svg`) come from
`tools/ui-import/fetch_season_images.sh`, fetched on 2026-10-12: the Wayback Machine's copies of
the hed_* files and the two SVGs (captures of 2024-11-04 and 2023-11-01), the rest from
`https://assets.krunker.io/img/chals/` as served that day (Last-Modified 2021-2023, ETag = the
file's MD5), each pinned by SHA-256. `icon_21` and the cards of weapons 13, 18, 20, 21 and 23-28
were not served (v7 shows a broken image for them too).

Images v7.1.4 loads from `https://assets.krunker.io/img/` that its tree lacks (the kill streak

(`live_assets.lock`, root `ui`), fetched on 2026-10-12 and pinned by SHA-256. These replace the

Krunker Box Office addition: `css/fonts/kn-symbols.ttf`, a subset (arrows, technical, box
drawing, blocks, geometric shapes, misc symbols, dingbats) of Adwaita Mono 34.1.0
Regular made with `pyftsubset --unicodes=U+2190-21FF,U+2300-23FF,U+2500-25FF,U+2600-26FF,U+2700-27BF,U+2B00-2BFF`

native engine uses it as its first per-glyph fallback (client/src/html/engine/text.c),
because Chrome draws these code points (e.g. the dev console's U+2715) from the
system's Adwaita Mono on the reference machine.

## Our files

- `css/krunknative.css` — Krunker Box Office's page overrides: transparent page over the scene,
  the class-preview hole, ads hidden, pointer events while the menu is closed, and the map
  terminal / interact progress bar markup v7 dropped (Krunker v3.1.1's rules; the elements
  are created by `client/src/ui/ui_terminal.c`).
- `css/hud.css` — the in-game HUD's crosshair and hit marker built from divs (v7 draws them on
  its overlay canvas).
- `css/ranked-kn.css` — the body of v7.1.4's Ranked window (its gen() is empty in the
  reconstruction and its stylesheet has no ranked rules): a few rules laying out v7's own
  window pieces, added at run time by `client/src/ui/ranked_ui.c`.
- `css/devconsole.css` + `css/fonts/lucon.ttf` — the offline build's developer console
  (`mod/devConsole.ts` in the jail tree): its injected `<style>` (only the root-relative font
  URL made relative). `client/src/ui/ui_console.c` adds the sheet at run time
  (`html_ui_add_stylesheet`) and builds the console's DOM the way the mod does;
  `client/src/ui/ui_mods.c` re-adds the mod's settings/controls rows.
- `css/editor-kn.css`, `css/viewer-kn.css`, `css/dat-gui.css` — see the editor / viewer pages.
- `js/kn-shim.js` — **web build only**: forwards the markup's inline handlers and the few
  listeners to C (`kn_ui_event`) and lets `client/src/html/web_dom.c` address elements
  (`knId`/`knEl`). No UI logic.
- `js/loader.js` — **web build only**: loads `client.js` when served over HTTP.

The native client runs no JavaScript: its engine ignores `<script>`. What v7's game JS
(src/index.js, src/libs/UI.js, src/libs/settings.js, src/ui/game.js) did to this page is
ported to C in `client/src/ui/`: `menu_ui.c` (`scaleBase()` for the 1700x900 design space
times `scaleUI` (0.7 by default), `UI.toggleMenu/toggleMenuHider/toggleWindow`,
`updatePlayInstructions()` — `CLICK TO PLAY` / `CLICK TO SPECTATE` when connected, v7's
loading ring before, the "Lost Connection" screen in `#instructionsUpdate` on a dead
connection — `showWindow` with each window's class and inline style, `updateClassPreview()`,
`mapInfo`), `ui_handlers.c` (the core inline handlers and the module handler chain),
`ui_windows.c` (window templates and generators), `ui_settings.c` / `ui_controls.c` (Game
Settings and Change Controls), `ui_loadout.c` (Change Loadout and its pickers), `store_ui.c`,
`account_ui.c`, `clan_ui.c`, `ranked_ui.c`, `servers_ui.c` (Servers, Server Finder, Custom
Games, Join, Connect) and `hud_ui.c` (the in-game `#inGameUI`, death and end screens).

Krunker Box Office additions on the v7 page (each restyled with v7's own classes): the menu bar's
"Ranked" button after Server Finder (v7 keeps the window and its `menu.btn.ranked` label but no
button), the "Connect" button next to Invite/Join (direct connect to `host[:port]`,
default port 21015, the console `connect` path), the "Exit" item and Settings > Client tab of
the desktop client, the Settings rows of the client mods (bhop, dev console binds), the
Audio Output row, the Lag Compensation slider, the map terminal and interact bar, and the
"Play Offline" tab on the connection error screen.

## Krunker v10 page tree (`v10/`)

`v10/` is the live krunker.io page (Krunker v10.0.2, mirrored 2026-10-13) as its own page
tree, for the runtime version toggle: `ui/` stays the v7.1.4 page. Natively it is selected
with `KRUNKNATIVE_UI_DIR=ui/v10`. It is not wired to a version setting yet, and `ui/v10/`
is not served on the web yet. It is generated by `python3 -I tools/ui-import/import.py
--ui ui --ref v10` (`tools/ui-import/v10_page.py`). Which source each file comes from:

| File(s) | Source |
|---|---|
| `index.html`, `social.html` | Byte copies of the **real served** pages (`https://krunker.io/`, `/social.html`, mirror `site.lock`), with the v7 rules applied: scripts, comments, og/twitter/description/apple metas (`platform/web/pwa.py` writes ours), preload/PWA links and `?build=` removed, URLs relativised, external links neutralised, canvas + our css/js added. |
| the markup inside `index.html`'s `#mainMenuUIMount`, `#notificationCenter`, `#gameAnnouncementEl`, `#matchmakingStatusEl`, `#matchEndSignupIncentives` | **Reconstructed from template strings**, not the rendered page. v10's menu is Svelte 5, so the served `index.html` has empty mount points. `tools/ui-import/v10_bundle.js` parses the client script (never runs it) and plays each boot component's mount code over a toy DOM in its initial, logged-out state (unknown runtime state reads as falsy). Expect the gaps of a static reading: lists built from server data (streams, popular games, news) are empty, and elements v10 shows or hides at run time keep their initial inline style. |
| `css/svelte.css` | **Reconstructed**: the 212 component stylesheets (`{hash, code}` strings of the bundle) that the Svelte runtime injects as `<style>` at mount, the mounted ones first. URLs moved one directory down. |
| `i18n-en.json` | **Reconstructed**: the bundle's inline `translations.en` (2170 keys). |
| `css/*.css` (Krunker's), `css/fonts/*`, `img/`, `textures/`, the other images | Byte copies of the served files (URL rewriting only). Each `.woff2` also gets a `.ttf`, and each `.webp` a `.webp.png` sidecar (the engine decodes neither). Files the live hosts 404 on (the Play subsets, `favicon.png`, `pro_scope.png`, ...) are v7's copies from `ui/`. |
| `windows/versions.txt` | The served `docs/versions.txt` (changelog). Other `windows/` templates: none yet. v10's `windows[n].gen()` builds them at run time, so they need the rendered-DOM capture. |
| `css/krunknative.css`, `css/hud.css`, `css/devconsole.css`, `css/ranked-kn.css`, `js/kn-shim.js`, `js/loader.js` | Ours: copies of `ui/`'s (the source of truth; the engine resolves page URLs inside the page root). |

Rendered page (not run yet, needs the user's approval because it runs Krunker's live client):
`node tools/ui-import/capture_v10_live.js <stage>` captures the booted DOM, every
`<style>`/adopted sheet, the popups (ranked, Turf Wars, leaderboards, guide, community),
settings/customize and `showWindow(1..54)` into `<stage>/v10-capture/`. It runs in sandboxed
headless Chromium (the proxy, an allow-list of krunker.io hosts, no POST and no WebSocket).
Once it has been run, files taken from it are marked here as **rendered**.

## Behaviour notes

- Clicking the dimmed `#instructionHolder` plays (a click with a window open
  just closes the window); ESC closes a window, otherwise toggles the menu.
- The class preview is Krunker's `#classPreviewCanvas` (750x600 CSS px inside
  the scaled `#menuClassContainer`). The UI logic reads its screen rectangle on
  setup, resize, menu open/close, class change and whenever its layout changes
  (resize observer); the client renders the selected class's player model at
  the box's device-pixel size and the page shows it as the canvas's bitmap
  (`html_dom_canvas_gl`), transparent around the model, so the canvas stays in
  the page's paint order (above `#instructionHolder`'s shade, under popups).
- Guests cannot set a name in Krunker's chrome; the Account window's username
  field ("Login"/"Register") doubles as the nickname.
- Links that leave the page in Krunker (`Hub` = `social.html`, Discord, Terms,
  installers, ...) open in a browser tab: `window.open` on the web, the system
  browser natively (http(s) only, relative links against `https://krunker.io/`;
  `client/src/ui/ui_dialog.c`). Krunker's `confirm()` / `prompt()` / `alert()`
  are the browser's on the web and the page's own `#genericPop` popup natively.
- Map selection happens through the Host Game window's map cards and the Custom
  Games list.
- Reference captures of the real v7.1.4 page and the uidiff scenarios:
  `doc/ref/krunker-v7.1.4/README.md`, `tools/uidiff/README.md`.

Preview: `make ui-test ARGS="render-page ..."` renders the page with the native
engine to a PNG (`--menu-preset` applies the menu-open state); `make web` +
`make web-serve` shows it in a browser with the full C UI logic. Opened from
`file://` the page is static (no windows, no menu state).

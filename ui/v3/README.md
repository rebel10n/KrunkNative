# ui/v3/ — the Krunker v3.1.1 menu page (version toggle)

The menu page of the "v3.1.1" Game version (Settings > General > Localization "Game version",
console `ruleset v3`; `client/include/ruleset_ui.h`, `doc/v10/version-toggle.md`). `ui/` stays the
v7.1.4 page. Natively the saved choice (`knRuleset` = `v3`) loads `ui/v3/index.html` at startup
(`KRUNKNATIVE_UI_DIR=ui/v3` does the same by hand); the web build serves `ui/` only and lists
v3.1.1 disabled (dist/web leaves `ui/v3` out).

Generated by `make ui-import-v3` (`tools/ui-import/v3_page.py`) from the `v3.1.1` tag's `ui/`
(`git archive`), the page the v3.1.1 port shipped (its provenance: that tag's `ui/README.md`).
Regenerate rather than edit; this README is the only file of ours the script keeps. Applied:

- every `<script>` removed and `js/` not copied (`js/kn-shim.js` / `js/loader.js` are the web
  build's glue; the native engine ignores scripts);
- `social.html`, `editor.html`, `viewer.html` and the stylesheets only they link left out: the hub,
  editor and viewer C code is written for v7.1.4's pages, so the native engine shows `ui/`'s for a
  page this tree lacks, and reads `ui/`'s copy of any stylesheet or image the tree lacks
  (client/src/html/engine/engine.c `fallback_dir`; e.g. the images of the borrowed windows below);
- `windows/`: only `versions.txt` (the v3.1.1 Changelog). v3.1.1's window templates were written
  for v3.1.1's C UI and its `windows.json` has no Settings / Controls tab lists; the C UI on main
  writes v7.1.4 window markup, so this page's windows are `ui/windows/` (ui_windows.c falls back);
- `css/v7-windows.css` (generated, linked last from `index.html`): v7.1.4's rules for the classes of
  those v7 window templates that v3.1.1's sheets do not define, so Settings, Controls, Loadout, Host,
  ... render styled inside v3.1.1's window chrome; it also hides `#propInstruct` (v3.1.1's prop
  hunt hint, which the C UI never hides).

What does not work like v3.1.1 yet:

- Gameplay: RULESET_V3_1_1 is not built (TODO(v3 ruleset)). The v3.1.1 Game version plays the
  v7.1.4 ruleset; the log, the Settings option, the console and each offline start say so.
- The in-game HUD: the C HUD writes v7.1.4 ids (`bottomLeftHealthBar`, `weapHolder`,
  `matchInfo`, `topLeft*`, `centerLeaderDisplay`, `miniMapCanvas`, `deathUIHolder`, the mode /
  spectate / comp holders, ...) that this page lacks, and v3.1.1's own HUD elements (`healthBar`,
  `healthValue`, `hudClassIcon`, `killCardHolder`, `scoreText`, ...) are not driven: health,
  weapons, minimap, scoreboard and death screen stay static or missing.
- Windows are v7.1.4's (above), by v3.1.1's window numbers, which agree except the footer's
  "Support" (v3.1.1 window 29, which v7.1.4 dropped): it does not open.
- The hub, editor and viewer are v7.1.4's pages (above), not v3.1.1's.
- Menu areas the C UI fills or toggles by v7.1.4 ids (e.g. `menuJNKCount`, `mLevelContV`,
  `fullMenHider`, `mainLogoFace`) keep v3.1.1's static markup.

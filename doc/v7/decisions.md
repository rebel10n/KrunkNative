# v7.1.4 upgrade: decisions

Decisions taken for the in-place upgrade from Krunker v3.1.1 to v7.1.4. The v3.1.1 port
stays on branch `v3.1.1` / tag `v3.1.1-parity`. Specs: krunkscript.md, map-logic.md,
editor.md, player-viewer.md (this directory).

| Topic | Decision |
|---|---|
| Parity target | v7.1.4 in place; v3.1.1 map JSON still loads, the way v7 loads it. Superseded in part by "Rulesets" below (user, 2026-10-13): one binary plays several Krunker versions, v7.1.4 stays the default and the reference for everything this file lists. |
| Rulesets (version toggle, doc/v10/version-toggle.md) | The user asked for a toggle between v3.1.1, v7.1.4 and v10.0.2 (2026-10-13). `shared/include/ruleset.h`: `RulesetId` (V3_1_1 not built yet, V7_1_4 the default, V10_0_2) and a `Ruleset` of const tables (constants, weapons, classes, modes, map catalogue, `MapDialect`, trigger / entity limits, KrunkScript feature mask, light-unit factor, page dir), in shared/src/rules/<ver>/. One ruleset per process: `game_constants` reads `g_rules_constants`, `Game.rules` is the ruleset `game_configure` took its tables from, code without a Game uses `rules_weapons()` / `rules_classes()`. Server: `server_bin --ruleset v7\|v10` (server.cfg `ruleset`, alias `game_version`; unknown ones exit 2), logged at start, in INIT (`NetInitPacket.ruleset` = RulesetId + 1, byte 17; a 17-byte INIT is v7), in the brain lobby tuple's meta and hello (`ruleset`), in the server-info query and in `mm_lobbies.ruleset` (0207, additive). HELLO gains a byte: the mask of rulesets the client can play (absent = v7 only); a server refuses a peer that cannot play its ruleset with ERROR `004010` (`NET_ERROR_CODE_RULESET`), never mixes versions. Client: adopts the server's ruleset on INIT (`game_adopt_rules`) and disconnects with a message when this build lacks it; Settings > General > Localization "Game version" (v3.1.1 listed as coming soon, disabled) and the console `ruleset [v7\|v10]` save `knRuleset`, which picks the offline sandbox's ruleset, quick join's (`/mm/seek-game?ruleset=`; quick join never crosses versions, joining a lobby by id may) and natively the menu page at startup: `ui/<Ruleset.ui_page_dir>/` (`KRUNKNATIVE_UI_DIR`, unless the user set it) when its index.html exists, else ui/ with a warning; a change offers a restart. ui/v10 has no window templates yet, so its windows (Settings included) are ui/'s v7 ones (ui_windows.c falls back) and the log warns; this is dev-facing until the live-v10 work adds them. The web build keeps ui/ (dist/web leaves ui/v10 out). The server browser badges rows that are not v7.1.4. v10's tables start as copies of v7's (TODO(v10-gameplay) in rules/v10/). |

| Public mode rotation | Public servers rotate modes and maps the way v7.1.4 does (user, 2026-10-13). At each round end, endGame builds 4 vote cards with genMatchList (`src/data/game.js:4632-4660, 5068-5133`): the FFA card first, then 2 random "mode,map" pairs, then 1 party pair. Each pair comes from a rotation map's `config.modes`, and the preventCustomGames modes are left out. With no votes, init picks a random card (`game.js:3401-3424`). The v7 server seeds each lobby with a random rotation map and a random mode among that map's modes that are in rotationModes `[0,2,3,19,25]` (`server/index.ts:1097-1114, 1178-1204, 3657-3659`). v7 has no mode weights: FFA's own card is the only bias. KN differences: (1) the server's `modes` list filters every pair. `modes rotation` (the deploy default, role variable `kn_gameserver_modes`) is rotationModes, so there is no party card. This is also what the v7.1.4 server ends up offering, because its applyMapVotingModeMetadata gives rotation maps rotationModes. Maps that offer none of the listed modes (Arena, Old_Burg, Throwback, Stockade) are not played. (2) KN reads each map's own `config.modes` from the map JSON, which the v7.1.4 server never loads (its maps.js entries only have name and fileName). On top of that, a pair needs the mode's objects: objectives, flags, domination zones or bomb sites (`game_map_offers_mode`, shared/src/game_config.c). (3) The first round's pair and the fallback with no cards both go through that check (`game_pick_rotation_pair`); earlier, a random map got a random mode, e.g. Kill Confirmed on Lostworld. (4) In a rotation of several modes, the server drops modes whose minPlayers or team count do not fit the lobby (`max_players` / `mode_max_players` / `mode_team_size`, server/src/config.c). (5) The listen port is part of the random seed, so instances started in the same second open on different pairs. |

# v7.1.4 upgrade: decisions

Decisions taken for the in-place upgrade from Krunker v3.1.1 to v7.1.4. The v3.1.1 port
stays on branch `v3.1.1` / tag `v3.1.1-parity`. Specs: krunkscript.md, map-logic.md,
editor.md, player-viewer.md (this directory).

| Topic | Decision |
|---|---|
| Parity target | v7.1.4 in place, no v3.1.1 mode. v3.1.1 map JSON still loads, the way v7 loads it. |
| Gameplay values | Adopt v7 movement, class, weapon and hitbox values. Re-record the shared/tests/inputs movement fixtures against v7.1.4. |
| Official maps | The catalogue becomes v7's 32 official maps with v7 indices (map-logic A6), under their plain names. The v3.1.1 maps stay playable as `311_<name>`, and v3.1.1's own `old_*` maps (from the v1.5.2 era) become `152_<name>` (user, 2026-10-12). |
| Ranked | Implement v7.1.4's ranked as closely as possible, replacing KN's own ranked (user, 2026-10-12). Its button is not in the left sidebar: it sits in the main menu bar with Server Finder (right after it, `button small buttonO`). Done (ranked-v7): one queue, a "Krunker Competitive" 4v4 comp lobby (config.hostTypes[1], isComp, Test Mode comp menu) playing Hardpoint on the comp maps by catalogue index, rankedClasses, eloK 32 / eloPer 120 / rankedDeduction 30 / rankedCooldown 2 h / minRankedLevel 15, ratings per season (`ranked_ratings`, 0204). KN's 1v1 / 2v2 / 4v4 queues and its two ranked modes (objective variant, first to 10 kills) are gone. v7 has no ranked mode: ids 37/38 stay reserved (no table entry). |
| UI | Re-import `ui/` from v7.1.4's pages with tools/ui-import, then re-wire the C UI logic (client/src/ui). Don't hand-port changes onto the v3 page. |
| GLTF and assets | Add cgltf (single header) and import v7's model and texture sets into `assets/` for skins, pets and animated models in the game and the viewer. |
| v7 bugs | Fix them, and document each fix in code. Don't replicate them. Byte-compatible serialisation quirks stay where the specs say so. |
| Offline account | The offline sandbox player counts as having an account (account-locked classes such as Hunter, Vince, Detective and Bowman unlock), as in v7's sandbox and custom games. |
| Embedded map config | It applies offline too. v7's sandbox discards it; we don't. |
| "player spawn" trigger event | It fires to map objects. v7.1.4 never dispatches it, but zombie_high relies on it. |
| Backend-only triggers | Triggers that give or take KR, save player data, or check premium/verified/level do nothing (or evaluate false) unless kn_brain supplies account data. |
| Settings presets | v7's Default / Pro / Performance / Custom, plus a KN "Beautiful" preset (highest quality): a fifth General-tab box and `#settingsPreset` option, its values in one table (`BEAUTIFUL`, client/src/ui/ui_settings.c). |
| Footer "Experiments" link | Dropped with its separator (v7's `abTestsPopup()` A/B test opt-in; KN runs no A/B tests). tools/ui-import removes it, so a re-import keeps it out. |
| Editor one-sided scaling | Keep Ctrl-hold to disable snapping, except while dragging an X/Z scale handle on prefabs that support one-sided scaling. |
| Seasons | The season system, Battle Pass and challenges are in scope at full v7.1.4 parity (user, 2026-10-12). Crafting and trading stay out of scope until requested. |
| Object Manager | A KrunkNative addition, not a v7.1.4 feature (user, 2026-10-12): a Garry's Mod style spawn menu named "Object Manager", toggled by F1 (`cont_objectManagerKey`, keyCode 112; F1's earlier Game Settings bind gave up its slot, `UI_CONTROL_OBJECT_MANAGER`). F1 opens it in game and frees the pointer; F1 or Escape closes it and re-locks the pointer; game input is suspended while it is open. Window 54 (KN-only), tabs Objects / Entities / NPCs / Weapons over a searchable icon grid (client/src/ui/object_manager_ui.c). Weapons: left click adds an extra loadout slot (`PLAYER_EXTRA_WEAPONS_MAX` 24, after the class loadout: `Player.loadout_base`), right click drops a WEAPON_PICKUP map object at the crosshair; with extra weapons the wheel steps through every slot (v7's wrap otherwise), the number row picks slots 1-9 (instead of its streak / taunt defaults), and a noSwap weapon in an extra slot does not lock the loadout. Rules (shared/src/object_manager.c): extra weapons and pickups for devs anywhere, for everyone in the offline sandbox and in custom / hosted games while the host's `knOmWeps` (a KN serverConfig key, default on) allows, never in public matchmade or ranked / comp games; objects, entities and NPCs for devs, the custom game's host and the sandbox. Objects tab: blocks, a ramp, a ladder, a jump pad and v7's model props at their default sizes, placed on the face the crosshair hits (on a floor, under a ceiling, or on the floor against a wall) and turned to face the player in quarter turns, so the AABB collision matches the model (ramps and ladders take map.js "d"). Undo (U, `cont_omUndoKey`) and Remove at the crosshair (Delete, `cont_omRemoveKey`) work in game, plus Remove / Undo buttons in the window; the remove tool takes the nearest spawned thing the crosshair reaches before a wall: the player's own, anyone's for devs and the host. NPCs tab: v7's built-in AIs, the zombies templates, Soul Sanctum's AIs and v7 bots (pinned to the spot); Entities tab: medals.js spawnables (on their own despawn timers), airdrops, the editor's scrap pickups and the zombies machines (map objects registered with the zombies runtime). Server-authoritative, a request bucket (10, 4/s) and caps (16 pickups / 64 objects / 12 NPCs / 24 entities per player; 256 objects / 32 NPCs / 64 entities per game; undo takes back the newest). Spawned map objects follow the map's own (uid = index, like builds), are replayed to joiners and go at the next round start. Packets 250-253 below (v7 peers only). |
| Public mode rotation | Public servers rotate modes and maps the way v7.1.4 does (user, 2026-10-13). At each round end, endGame builds 4 vote cards with genMatchList (`src/data/game.js:4632-4660, 5068-5133`): the FFA card first, then 2 random "mode,map" pairs, then 1 party pair. Each pair comes from a rotation map's `config.modes`, and the preventCustomGames modes are left out. With no votes, init picks a random card (`game.js:3401-3424`). The v7 server seeds each lobby with a random rotation map and a random mode among that map's modes that are in rotationModes `[0,2,3,19,25]` (`server/index.ts:1097-1114, 1178-1204, 3657-3659`). v7 has no mode weights: FFA's own card is the only bias. KN differences: (1) the server's `modes` list filters every pair. `modes rotation` (the deploy default, role variable `kn_gameserver_modes`) is rotationModes, so there is no party card. This is also what the v7.1.4 server ends up offering, because its applyMapVotingModeMetadata gives rotation maps rotationModes. Maps that offer none of the listed modes (Arena, Old_Burg, Throwback, Stockade) are not played. (2) KN reads each map's own `config.modes` from the map JSON, which the v7.1.4 server never loads (its maps.js entries only have name and fileName). On top of that, a pair needs the mode's objects: objectives, flags, domination zones or bomb sites (`game_map_offers_mode`, shared/src/game_config.c). (3) The first round's pair and the fallback with no cards both go through that check (`game_pick_rotation_pair`); earlier, a random map got a random mode, e.g. Kill Confirmed on Lostworld. (4) In a rotation of several modes, the server drops modes whose minPlayers or team count do not fit the lobby (`max_players` / `mode_max_players` / `mode_team_size`, server/src/config.c). (5) The listen port is part of the random seed, so instances started in the same second open on different pairs. |

New packets are gated on `NET_PROTOCOL_MINOR` (3 = `NET_PROTOCOL_MINOR_V7`, set by map-A; don't bump it again without asking the coordinator). The client negotiates per server, from the INIT version.

`NET_PROTOCOL_PATCH` (1, player-viewer WP-C) rides in HELLO and INIT (a 2-byte HELLO reads as patch 0). From 1.3.1, ENT V8, SPAWN V3 and RECON V2 carry the v7 fields; `net_peer_has_wpc(minor, patch)` gates them, and 1.3.0 peers keep the shorter forms. The ENT, SPAWN, RECON, HELLO and INIT readers accept longer payloads (prefix read).

# v7.1.4 upgrade: decisions

Decisions taken for the in-place upgrade from Krunker v3.1.1 to v7.1.4. The v3.1.1 port
stays on branch `v3.1.1` / tag `v3.1.1-parity`. Specs: krunkscript.md, map-logic.md,
editor.md, player-viewer.md (this directory).

| Topic | Decision |
|---|---|
| Parity target | v7.1.4 in place; v3.1.1 map JSON still loads, the way v7 loads it. Superseded by "Krunker v10.0.2 is the only version" below (user, 2026-10-13): v10.0.2 is the gameplay target; this file stays the reference for everything v10 keeps from v7.1.4. |
| Krunker v10.0.2 is the only version (user, 2026-10-13) | "let's just ditch the client versioning and only keep v10, call it off for everything else and just nuke earlier versions. v10 remains the definitive and only version of the client. we don't want to add bloat." The version toggle (v3.1.1 / v7.1.4 / v10.0.2 rulesets, the v1.5.6 and v3.1.1 menu pages) is removed: no Settings "Game version" row, no console `ruleset`, no `knRuleset` storage (a saved one is deleted at startup), no restart prompts or "plays v7.1.4" notices, no server-browser version badges, no `server_bin --ruleset` (exit 2: unknown option) and no server.cfg `ruleset` / `game_version` (ignored with an error line); `ui/v3/`, `ui/v156/`, their importers (`v3_page.py`, `v156_page.py`, `import.py --ref v3 / v156`), `make ui-import-v3 / ui-import-v156 / smoke-v156` and `tools/uidiff/v156` are deleted. Gameplay: `shared/include/ruleset.h` keeps one `Ruleset` (v10.0.2: constants, weapon / class / mode tables, map catalogue, trigger / entity / archetype limits, light units, ranked rules) behind `ruleset_current()` / `Game.rules`, with no `RulesetId`; `shared/src/rules/v7/` is gone and `rules/v10/` stands alone (`game_constants` is v10's table, v10's mode changes are in `shared/src/modes/modes.c`, the hurtboxScale rows in the option tables, the posed hit boxes in every mode but Prop Hunt, maps read the v10 way, the v7.1.4 weapon definitions stay in `shared/src/weapons/` for the entries v10 did not rebalance and for upgradeWeapons). Wire: HELLO's ruleset byte is sent as the v10 bit only (`NET_HELLO_RULESETS` 1 << 2) and never read by the server (nothing is refused for it); INIT's byte is always 3 (`NET_INIT_RULESET`) and never read by the client; the brain lobby meta / hello and the server-info query say `"ruleset":"v10"`, quick join sends `?ruleset=v10` and skips lobbies that announce another version (a lobby announcing none still matches), ranked matches record "v10" (the `brain.ranked.ruleset` key is gone). `mm_lobbies.ruleset` (0207) stays. UI: the v10 page is `ui/` itself since 2026-10-14 (the v7.1.4 page and its `ui/v10/` staging tree are gone, with the C UI's v7 page branches and the HTML engine's read-through of `ui/` for page trees under it); uidiff compares against the v10 captures only (ui/README.md, tools/uidiff/README.md). |

| Public mode rotation | Public servers rotate modes and maps the way v7.1.4 does (user, 2026-10-13). At each round end, endGame builds 4 vote cards with genMatchList (`src/data/game.js:4632-4660, 5068-5133`): the FFA card first, then 2 random "mode,map" pairs, then 1 party pair. Each pair comes from a rotation map's `config.modes`, and the preventCustomGames modes are left out. With no votes, init picks a random card (`game.js:3401-3424`). The v7 server seeds each lobby with a random rotation map and a random mode among that map's modes that are in rotationModes `[0,2,3,19,25]` (`server/index.ts:1097-1114, 1178-1204, 3657-3659`). v7 has no mode weights: FFA's own card is the only bias. KN differences: (1) the server's `modes` list filters every pair. `modes rotation` (the deploy default, role variable `kn_gameserver_modes`) is rotationModes, so there is no party card. This is also what the v7.1.4 server ends up offering, because its applyMapVotingModeMetadata gives rotation maps rotationModes. Maps that offer none of the listed modes (Arena, Old_Burg, Throwback, Stockade) are not played. (2) KN reads each map's own `config.modes` from the map JSON, which the v7.1.4 server never loads (its maps.js entries only have name and fileName). On top of that, a pair needs the mode's objects: objectives, flags, domination zones or bomb sites (`game_map_offers_mode`, shared/src/game_config.c). (3) The first round's pair and the fallback with no cards both go through that check (`game_pick_rotation_pair`); earlier, a random map got a random mode, e.g. Kill Confirmed on Lostworld. (4) In a rotation of several modes, the server drops modes whose minPlayers or team count do not fit the lobby (`max_players` / `mode_max_players` / `mode_team_size`, server/src/config.c). (5) The listen port is part of the random seed, so instances started in the same second open on different pairs. |

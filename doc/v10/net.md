# v10.0.2 network protocol vs v7.1.4

Sources: `v10.0.2.js` (line numbers refer to the identifier-renamed copy `~/.cache/kn-v10/v10.js`,
which keeps the original line layout) and the v7.1.4 reference at
`/home/user/jails/kru/src/Krunker_v7.1.4` (`packets.json`, `src/libs/io-client.js`,
`src/libs/ClientManager.js`, `src/index.js`, `src/data/game.js`). The bundle contains both the
client and the shared server simulation (`isServer` branches, `game.broadcast(...)`), so
server-to-client shapes can be read off the sender.

KrunkNative does not speak Krunker's wire format. It has its own numeric packet ids over knet
(`doc/transport.md`, `shared/include/shared.h` `NET_PACKET_*`). The wire ids below matter
only as names to map onto new `NET_PACKET_*` types, and for parity in the payload contents.

### Entities (new subsystem, wire side)

These packets carry KrunkScript "entities" (archetypes defined in the map/script; see
krunkscript and map-format docs). Server limits come from config (19650-19660):
`entityLimit` 64 (also hard-coded in `spawn`, 184290), `entityStateKeys` 32,

entities up to 64 ticks on an older baseline, 185740), `entitySimBudgetMs` 2.

on decode (`decodeState` via `addPrefix`, 168575).
Server hooks: `onEntityInit`, `onEntitySpawn`, `onEntityAttach`, `onEntityEvent`,
`onEntityDamage` (184304, 191471, 184966, 185323, 185861).

### Invite / Join

v10 has no party system. `copyInviteLink` copies `https://<host>/?game=<gameId>` (#inviteButton
"Copied URL" for 1250 ms); `openJoinWindow` joins a game link / code read from the clipboard, else
opens windows[23] (#gameURL + `joinGame()`); its parser takes `/?game=` / `/?party=` links and
`/^([A-Z]+):(\w+)$/` codes. The profile window's Friends tab joins with `openURL('/?game=<gid>', 1)`.
A game that needs a password: v10's server sends `ENTER_CODE` (popup `gameCode()`, `code` packet,
`UPDATE_CODE_TIMER`, `CODE_PASSED`); server_bin refuses the join (ERROR 004005) and the client shows
the same popup, then joins the same game again with the password in its JOIN packet (no countdown).

## 6. Port notes

- Implement: entity packets (with KrunkScript entities), `PLAYER_POSE`, `PLAYER_LOCKS`, the
  `SYNC_PLAYER` controlled-entity tail, `joinedRank` plus the ranked queue flow (against
  kn_brain, not FRVR), and optionally the event-bus friends/DM service in kn_brain.
- Do not implement `CHEAT_CHECK` / `ccr`. It is a server-pushed remote code execution
  channel (XOR-obfuscated JS run through `eval`). The native client has no JS engine, so the
  only safe port is to not send or answer it.
- `CHARGE_CONSENT_REQUEST/RESPONSE` is a server-initiated "spend currency?" confirmation
  (15 s timeout, guess: in-game KrunkScript purchases). Port it only if KrunkScript
  monetization is ported.
- `sdc` / `swu` / Discord / webpush / FRVR auth are live-service features. They map onto
  kn_brain endpoints if wanted; they are not gameplay.
- Version toggle: the knet protocol stays one protocol. Add a ruleset id to the join/JOIN
  packet so the server can refuse cross-version clients, rather than per-version wire formats.

## 7. KrunkNative packet ids: the NET_PACKET_EXT envelope

Coordinator decision (2026-10-13): the 1-byte knet type stays. 250-253 are the Object Manager's
and 254 is `NET_PACKET_EXT`, an envelope whose payload is a little-endian u16 subtype followed
by the subtype's body (at most 510 bytes). Every packet added from v10.0.2 on is an EXT subtype.
It needs protocol 1.4 (`NET_PROTOCOL_MINOR` 4 = `NET_PROTOCOL_MINOR_EXT`): servers send EXT only
to peers whose HELLO announced 1.4, receivers ignore subtypes they don't know. Source of truth:
`shared/include/net_ext.h` (`NetExtSubtype`, `net_ext_pack` / `net_ext_unpack`).
